Introduce the team: Team Foundry, Team 46 (Aditya, Farhan, Uday, Miguel). Hook. Agents can now build geospatial datasets in minutes: find sites, check imagery, write the answer. But a program officer can't tell whether to trust the result, and today nobody can. That's the gap Clay named as the #1 unmet need. We built the evaluator. (~30 s)

Our idea

Judge the work, not just the answer

●

Record

Every model call and every tool call is captured as an OpenTelemetry span: what the agent saw, what it decided, what each tool returned.

✓

Verify

Every claim must cite the tool result it came from. Code checks the value is really there, and that each site is inside the area that was asked for.

⚖

Judge

Three AI judges from three different companies score the parts code can't, each vote tied to the step it relied on.

Nothing is judged on the final answer alone. The trace is the evidence.

Three moves. Record: we trace decisions, not just telemetry. Verify: claims cite tool results, and code checks them, no opinion involved. Judge: the rest goes to a cross-family tribunal. Next: let's watch it judge a real run. (~40 s)

Calibration: we plant one defect at a time and check the right criterion drops. All three did. Agreement: Krippendorff's alpha 0.50 across our runs, close to the 0.56 human experts reached in the GRA paper. Be honest: the CI is wide because there are 7 runs. (~45 s)

The traces don't lie

It caught bugs in our own agent

Before
FAILED

Texas parks prompt: no answer, $1.50 spent. The trace showed why, step by step.

After the fixes
85.4 · High

Same prompt on AgentCore: 0 errors, 15 / 15 claims verified, 8 / 8 sites inside Texas, $0.81.

"Northern California" resolved to a 20-metre building in San Francisco, so every search came back empty.
LGND sign-in expired after exactly 300 seconds; every call after 290 s failed.
Narrowed searches (a 16 km circle around a park) were silently widened to all of Texas.
This is the point of the whole thing. Without the traces we'd have blamed the model. The evaluator showed the harness was at fault: the wrong area, an expired token, searches widened. We fixed them and the same prompt went from FAILED to 85.4, High. That's the trust story ADB needs: you can see exactly why. (~45 s)

Built to plug in

Every part is swappable by config

Tools (MCP)

AWS Open Data (RODA) and LGND Geo imagery search

Trace

OpenTelemetry spans to an S3 archive; exporter swapped by config, proved in CI

Evaluate

Measured checks + judge tribunal on Bedrock; Team Foundry console (FastAPI)

ADB's rubric → one YAML fileJudges → configModels → configTracing backend → configInfra → CDK

Replays work offline: any archived run re-scores from its trace, without calling the agent again.

Technology slide for the judges: AgentCore, Strands, MCP, OpenTelemetry, S3, CDK, FastAPI. The design point: OpenTelemetry is the one contract, everything else plugs in. When ADB's rubric arrives, it's a YAML file, no code. (~30 s)

What it proves, and what's next

Honest about the limits

It proves today

Each claim matches the tool output it cites, each site is in the requested area, and three independent judges agree how well the work was done.

Not yet

Whether a site is really a data center. That needs an answer key, and ADB's own rubric.

Next

An answer key (e.g. US solar sites), ADB's rubric as a file, expert ratings of the judges, plain-language verdicts, and checking every condition in the prompt.

Plain-language verdicts and prompt compliance are being built today, as separate slices.

End on honesty: we check the agent against its own evidence, not against the world, yet. The path there is concrete. Thank the judges; open for questions. (~30 s)
