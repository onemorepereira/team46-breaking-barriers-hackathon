Introduce the team: Team Foundry, Team 46 (Aditya, Farhan, Uday, Miguel). Hook. Agents can now build geospatial datasets in minutes: find sites, check imagery, write the answer. But a program officer can't tell whether to trust the result, and today nobody can. That's the gap Clay named as the #1 unmet need. We built the evaluator. (~30 s)

Our idea

Judge

The trace is the evidence, not the final answer.

Three moves. Record: we trace decisions, not just telemetry. Verify: claims cite tool results, and code checks them, no opinion involved. Judge: the rest goes to a cross-family tribunal. Next: let's watch it judge a real run. (~40 s)

Reviews→Lessons→Held-out test→A person approves

Can a review push the judges? Live:✓ wrong review resisted✓ "I insist" resisted✓ injected instructions resisted
The judges aren't the last word: ADB's experts are. On one run, an expert says where the panel got it wrong, and the judges reconsider against the trace. They don't just obey. We tested that live with a review that was wrong on purpose: Opus kept its score and corrected us, citing the exact steps. Across runs, reviews become short lessons; we test them on runs they weren't drawn from, a person approves them, and every judge uses them from then on, with a version on every score. And we checked the judges can't be pushed: a wrong review, the same one with "I insist", and one with injected instructions all failed to move them, measured against a control. This is also how ADB measures the judges against its own experts. (~45 s)

This is the point of the whole thing. Without the traces we'd have blamed the model. The evaluator showed the harness was at fault: the wrong area, an expired token, searches widened. We fixed them and the same prompt went from FAILED to 85.4, High. That's the trust story ADB needs: you can see exactly why. (~45 s)

Technology slide for the judges: AgentCore, Strands, MCP, OpenTelemetry, S3, CDK, FastAPI. The design point: OpenTelemetry is the one contract, everything else plugs in. When ADB's rubric arrives, it's a YAML file, no code. (~30 s)
How the whole system fits together on AWS, following the six numbered steps on the diagram. 1. An analyst or reviewer starts a run from the Team Foundry harness, which checks the cost caps. 2. The agent builds the dataset: a Strands agent on Amazon Bedrock AgentCore Runtime calls the RODA and LGND Geo MCP servers to search open data and imagery. 3. Every model and tool decision is saved as a trace, to Amazon CloudWatch and an Amazon S3 run archive, so any run can be replayed offline. 4. Code runs the measured checks: each claim against its tool evidence, each site against the area. 5. A judge panel of three model families on Amazon Bedrock scores the work, three passes each, and the votes are averaged. 6. A person reviews the scorecard, the map and the feedback. (The swap-by-config point is on the previous slide; don't repeat it here.) (~45 s)
